## 生成器
Java 对应物：Iterator + 惰性求值，或者 Stream 的惰性管道。Java 里你要手写 hasNext()/next()，Python 用 yield 一个关键字就搞定。

核心机制：函数里出现 yield，调用它不会立即执行函数体，而是返回一个生成器对象；每次 next() 才推进到下一个 yield，并在那里暂停、保留局部状态。

区别是 Python 的生成器可以“暂停/恢复”，写起来更像协程的雏形。看到 yield 就理解为“这里吐一个值然后挂起”。

生成器只能消费一次，遍历完就空了；想多次用要重新创建。

## 协程
协程是可以在执行中途暂停、并在之后从暂停点恢复执行的函数

和线程、进程的关键差异在调度方式和切换成本：

线程是抢占式：OS 随时可能打断一个线程去跑另一个，你不知道什么时候被切走，所以共享数据要加锁。切换要陷入内核，成本高。

协程是协作式：只有代码执行到 await 时才会让出，不让出就一直跑。切换发生在用户态，就是保存/恢复几个寄存器，成本极低。也正因为“不让出就不切换”，单线程内不存在并发修改的竞态，大多数场景不用锁。

用一个类比：线程像多个厨师抢一口锅，OS 是那个不断把锅从一个人手里夺走给另一个人的经理；协程像一个厨师在做多道菜，菜要炖的时候主动去看另一道菜，炖好了再回来——全程一个人，但没闲着。

重要澄清：协程不是并行。单线程事件循环里，同一时刻只有一个协程在跑。它的价值是“在等待 I/O 的时候去干别的”，不是“同时算多个东西”。想利用多核，协程帮不上忙，得靠多进程或线程池。

## async/await
单线程协程
async def 定义协程函数，调用它返回一个协程对象，不立即执行

await 表示“这里可能要等 I/O，把控制权交出去，让事件循环去跑别的协程”

必须用 asyncio.run(...) 或在一个已运行的 event loop 里驱动

为什么 Agent 代码里大量出现：Agent 要同时调多个工具、同时请求多个 LLM、同时查多个检索源。这些都是 I/O 等待，用 async 并发能大幅降延迟。LangGraph、AutoGen 的接口大量是 async def

协程里尽量不写CPU密集型代码，只写"会让出控制权"的代码，如果要写CPU密集型代码，也不能堵住时间循环很久，一些小计算，拼接字符串等是可以的，就是关键要看操作堵住CPU多久，堵的不厉害就可以写

## 类型注解
// Java
public String greet(String name, int times) { ... }
// Python
def greet(name: str, times: int) -> str: ...

java中强制声明类型，且编译校验
python不强制声明，且不校验，只是给人和工具看的，不是契约，只是注释
所以python传参的数据类型如果有要求，需要自己校验
