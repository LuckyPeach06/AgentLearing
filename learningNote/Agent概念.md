## token
Token 是模型处理文本的最小单位,由分词器把文本切出来的片段。一个英文单词大约 1 个 token,中文一个字通常也是 1 个 token。它有三个意义:第一是计费单位,API 按输入加输出的 token 数收费;第二是上下文窗口的单位,模型能处理的文本长度就是用 token 衡量的;第三是成本设计的依据,同样一句话,用什么语言、怎么写,直接影响 token 消耗。

## 上下文窗口
上下文窗口是模型单次请求能处理的输入加输出的最大 token 数,是模型训练时就定死的上限,不是可配置项。它带来两个工程问题:一是超限直接报错;二是 Agent 场景下它是持续消耗的核心资源——多轮对话、工具调用的观察结果回填,每一步都在吃窗口。还有个大坑是"迷失中间"(lost in the middle):窗口很长时,模型对中间部分P的内容关注度会下降。

实践上我的处理方式:我做 ReAct 智能体时,每一步都把历史塞回上下文,步数多了容易爆窗口,所以必须设 max_steps,并且对历史做裁剪或摘要;做 RAG 时只把最相关的片段塞进去,而不是把整个文档喂给模型。

## temperature
温度是控制生成随机性的超参数,一般范围 0 到 2。温度越低,输出越确定、越保守;越高越发散、越有创意。它调整的是模型输出概率分布的平滑程度,不影响模型的知识水平。选值要看场景:需要稳定解析的场景用 0 或接近 0，创意类场景如写文案、头脑风暴,才会用到 0.7 以上。

## System prompt
System Prompt 系统提示词：是消息里 role=system 的那一条,用来设定模型的人设、行为边界和输出规则,比如"你是客服助手,回答要简洁,不知道就说不知道"。它的作用贯穿整个对话——只要还在上下文窗口内,模型每轮回复都会"记得"它。工程上有两点关键认识:第一,它是把产品需求翻译成模型指令的载体,所以需要像代码一样做版本管理和测试,这就是提示词工程的核心;第二,它不是安全边界——用户输入可能通过提示注入绕过它,真正的安全约束必须做在工具层和代码层
